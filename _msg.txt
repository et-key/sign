refactor: parser.sn はトークン列を縮めない（位置だけを進める）

コメントに書かれていた2つの「要点」は、どちらも同じ根から出ていた。

  【要点1】1要素リストはスカラーと同型なので、残りが1個になった時点で
           場合分けが要る（`|ts| = 1 : ts`）
  【要点2】尽きたことを __ で表すと次の呼び出しが完全性公理で崩壊するので、
           番兵の値（`sentinel : `end``）を返す

根は「リストが縮んでいく」ことである。縮めなければ1個にも空にもならないので、
両方まとめて消える——n_queens.sn が「空を作らずに済ませることが、この問題に
対する唯一の素直な答えである」と書いているのと同じ形。

  peek / rest / sentinel が要らなくなった（3つの定義が消えた）
  範囲外の添字は __ を返し、__ との比較は偽になるので、終端の判定はそれで足りる

**要点1 の場合分けは、実は末尾のトークンを壊していた。** `peek : ts ? |ts| = 1 : ts`
は残りが1個のとき**器ごと**返すため、末尾だけ `["3"]` と1要素リストに包まれて
いた。トークンはトークンであって、トークンの入れ物ではない。

  1 + 2 * 3   [["1","+"],[["2","*"],["3"]]]  →  [["1","+"],[["2","*"],"3"]]

Pass 4 への還元:  90 → 0。`.ist` も未解決 0 になった。

  fst : Struct -> Struct
  snd : Struct -> Int
  mul_go : Struct List Int -> Struct
  mul_lv : List Int -> Struct
  add_go : Struct List Int -> Struct
  expr : List -> Struct

`factor := token` は関数にしなかった。関数にすると `fst`/`snd` が factor の結果と
mul_lv の結果の両方で呼ばれ、形について多相になる（値は同じだが型が決まらない）。
「その位置のトークン」そのものなので、添字で書くのが素直である。

併せて `.st` の1つを直した。**仮引数はフィールド名になれない。** 仮引数は実行時に
値が入る場所であって名前ではないのに、`f : l i ? l ' i` の `i` がフィールド要求
`{i}` として記録されていた。type_system.md §2 が OK 例として明示している
`list ' i`（`i` は実行時変数でよい）がまさにこの形なので、取り違えると添字の
書き方が全部「フィールド要求」に化ける。
