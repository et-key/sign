fix: 返値型の不動点を2相で回す（仮引数の狭まりは単調な変化ではない）

返値型の不動点は `__`（底）から単調に上がる設計である。ところが**仮引数の型は
後から狭まる**——呼び出しサイトからの具体化（Pass 1b の Layer 2 版）は束を下る
変化であり、単調ではない。両方を1つのループで回すと、一度上がった返値は二度と
狭まらない。再帰の枝が前の周回の値を読み、それが自分を養い続けるからである。

`unwind : st d ?` がこれを踏んでいた。

  arm 0  unwind (pop st) d   ← 自分の返値を読む
  arm 1  st

`st` は初回に既定の `Atom` なので返値が `Atom` へ上がる。呼び出しサイトから
`st` が `Int` へ狭まった後も、arm 0 が古い `Atom` を返し続けるため
`join(Atom, Int) = Atom` で固定されていた。

1相目で仮引数の型を確定させ、返値を底へ戻して2相目を回す。2相目は最初から
正しい仮引数の型で始まるので、基底ケースが決めた型がそのまま残る。文書が
「初回は再帰の枝が何も寄与せず、基底ケースだけが型を決める」と書いている通りの
ことを、仮引数が確定した後にもう一度やっているだけである。

  unwind  : Int Int -> Atom  →  Int Int -> Int
  next_st : Int Int -> Atom  →  Int Int -> Int | List
  walk    : ... -> Atom      →  ... -> String

Pass 4 への還元（preprocess.sn）: 44 → 4。族のままは 0 になった。

残る4つは `Int | List` で、これは**本物**である——インデントスタックは空のとき
スカラーの 0、中身があれば `List(Int)` なので、値として本当に両方を流れる。
型が嘘をついているのではなく、多相であることを正しく書き写している。

底へ戻すときは「種である」という印も立て直す。上がらなかった種を答えとして報告
しないための旗なので、2相目でも同じ扱いが要る（ポイントフリーの返値は演算子表から
読めているので種ではない——そちらは印を消す）。
