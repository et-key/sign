Sign is johnny-shaman's own language design project (category-theory-grounded, heapless/systems-oriented, no reserved words — see `AGENTS.md`/`documents/ja-jp/impl/0_design_principles.md` for the philosophy, which is authoritative and should be read before reasoning about the language).

**Active implementation lives in `alpha/javascript/`** (JS reimplementation of lexer/Pass1/Pass1b/Pass2/Pass3/interpreter, matching the canonical grammar/spec under `documents/ja-jp/impl/`). `pre_alpha/` **was deleted from the repo on 2026-08-13** (PR #293) and zipped to a gitignored `pre_alpha_archive.zip`; its record lives in `documents/ja-jp/impl/appendix/pre_alpha.md`, which opens by saying **do not use pre-alpha code as a design reference**. `LanguageServer/`, `utility/`, `tools/` are older/parallel efforts, still unexamined.

**Why:** The user chose JS-first-then-formalize over a mentor's earlier suggestion to do Lean/formal-proofs-first, for incremental, empirically-grounded progress (see [[feedback-implementation-style]]). The working loop is: small implementation step → probe reveals a real structural bug → fix → document in `alpha/javascript/README.md` and/or the canonical spec docs.

**Status as of 2026-08-08:** `alpha/javascript` has a working tree-walking interpreter, Pass1/1a/1b/2/3, and a browser-based playground. Two full audit passes are now closed: the original guide-example audit ([[project-sign-bracket-destructuring]] — destructuring/match_case/push/unshift/range/pointfree/negative-index/`~`-flatten, all done) and a from-scratch real-program stress test writing 8-Queens ([[project-sign-8queens-audit]] — 8 more real bugs found and fixed, the original clean recursive design now runs correctly for N=1..8). The operator-table audit ([[project-sign-operator-table-audit]]) is nearly closed too — `==`/`!==` (structural (in)equality, commits 94610e4/346851f) now work; only `===` evaluation remains open, needing constructor-provenance tracking (`' !__`), a bigger separate feature — not a design question anymore, just not built yet.

**`$`/`@`/`#` (address ops) and automatic currying are now both implemented** (commits 1651c84, 10f0777). `$`/`@`/`#` are reference cells (`{get,set}`) for identifier/get_prop targets (real read/write) and a read-only snapshot form for arbitrary expressions. Automatic currying is a fully static (pass2-only) mechanism: `markUndersaturatedApplies` renames any arity-short apply chain to `"partial_apply"` after `reduceAll` finishes, and the interpreter has a dedicated case that unconditionally builds a partial closure — no runtime "is this short?" check anywhere, honoring the "compiler must decide everything, never punt to runtime" principle this was built around (see [[project-sign-currying-design]] for the full argument and build history). Confirmed: `f 1` for a 3-arg `f`, then `(f 1) 2 3` or `((f 1) 2) 3`, completes correctly with no `$`/`@` needed; the manual `$[...]` form still works unchanged alongside it. **What's still missing:** only the "shape/layout" pass that would be needed for addressing into arbitrary Struct fields (not needed for anything built so far — currying/$/@ only ever touch identifiers, list indices, or snapshots, all of which JS's own value representation already handles). No Pass4/codegen.

Also see: a design-only follow-up, [[project-sign-return-value-addressing-design]], on functions returning String/List (implicit references, proposed sret-style resolution) — no alpha/javascript angle since JS's GC already makes it a non-issue there.

**`string_and_comment.md` audit also closed** (2026-08-08, see [[project-sign-string-comment-audit]]): empty-string≅Unit, string indexing as characters, and a grammar bug where code and comments couldn't coexist in one file (`Program`'s comment/code either-or) — the latter fix also surfaced and fixed a hidden PEG-non-backtracking bug inside the `comment` rule itself. No inline (trailing) comments is confirmed-deliberate design, not a gap.

**Tail-call optimization implemented too** (2026-08-08, commit 4f5cca6, see [[project-sign-tco]]): a trampoline in `applyClosure`/`evaluateTail`. High-priority precisely because Sign has no loop keywords at all — recursion is the only iteration mechanism, so the interpreter's recursion-depth ceiling directly caps the language's expressiveness. Deep mutual recursion that crashed around n=2000 before now runs 1,000,000+ deep in ~560ms; non-tail recursion is still correctly bounded by the JS stack (confirmed this stays selective, not a blanket exemption).

**How to apply:** `alpha/javascript/README.md` is kept meticulously up to date after every change — read it first for exact current status/known-limitations rather than assuming from this note, since it changes daily. For $/@/#/currying/type-system work specifically, [[project-sign-currying-design]] has the load-bearing design reasoning and full implementation history — read that before touching any of it.
