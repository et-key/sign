### 0.4 圏論で言えること・言えないこと

1. **4つの読みは、種類の対で尽きる。** 隣り合う2項の種類の対は、値値・関数関数・関数値・値関数の4つしかない。
   - 構築：零対象のある圏での標準の射 A ⊔ B → A × B。これが同型なら双積になる。
   - 合成：f ; g（図式の順）。
   - 適用：評価射 ev : B^A × A → B。
   - 逆適用：ev の前に対称の同型 σ を置いたもの。だから記法の違い（糖衣）でよい。
2. **書いた順に実行することから、2つの順が出る。**
   - 合成 > 適用：`f g x` で適用を先にすると、g が先に走る。
   - 適用 > 逆適用：`f x g` で逆適用を先にすると、f(g(x)) になる。
3. **構築と合成には順が要らない。** 2つは同じ項を取り合わず、どちらも種類を変えない。
4. **構築と適用の上下は、圏論からは出ない。**
   - カリー化の随伴 Hom(X × A, B) ≅ Hom(X, B^A) があるので、アリティどおりならどちらの木でも値は同じ。
   - 利用者も、この式を文書から外す必要は無かったと言っている（U〔答え〕10-16 22:09「外す必要までは無かったと思う」）。
   - 割れるのはアリティと実引数の数が合わないときだけで、そこは利用者の選択（08-27）で決める。
5. **零対象を持つ圏がカルテシアン閉なら、その圏は自明である。**
   - 証明：− × A は左随伴なので 0 × A ≅ 0。0 が終対象でもあるので 0 × A ≅ 1 × A ≅ A。だから A ≅ 0。
   - だから「構築＝零対象つきの双積」と「適用＝同じ積での評価射」は、それだけで同じ圏の同じ積の上に乗らない。分配律を足す必要は無い（カルテシアン閉圏はもともと分配的）。
   - 零対象を持つ分配圏が自明であることは、これとは別の事実（A ≅ A × 1 ≅ A × 0 ≅ 0）。
   - U 10-11 08:40 の「空間の圏」と「量の圏」は「噛み合わない」という言葉と、向きが合う（R）。
   - 帰結：表は導出ではなく、利用者の約束（08-27）である。
   - 「適用の右に来た構築は、対象1つではなく並びである」は定理からは出ない。設計の読み（R）で、U 09-24 00:57「余積のリスト化は、実はイテレータオブジェクトの生成と同義」と合う。
   - 「`_`＝零対象」もモデルの選び方（R）。U 10-17 01:03 は、値と関数の関係が同型か随伴かを嗅ぎ分けよと言っている。
   - 抜け道：閉構造を別のモノイダル積 ⊗ で取れば、自明でない例がある（⊕ と ⊗）。その場合、実引数の組は ⊗ の側で、構築の ⊕ とは別物になる。
6. **「値＝大域元」と「`_`＝零対象」は、同じ圏ではそのまま並べられない。** 1 ≅ 0 になり、どの対象の大域元も1つしかなくなる。だから値を A、関数を L という種類として扱うだけにした。
7. **`_` の顔のうち、数学として言えるもの。**
   - 構築の単位：0 ⊕ A ≅ A。U 10-14 11:58「_ \a = \a = `a`」と合う。11:56 は、文字の並びを文字列にする話。
   - 零射の吸収：f ; 0 = 0。U 10-14 03:10「f _ は _」と合う。
     - これは合成の読みで、U 10-15 23:38「[!_] _ という関数合成」とも合う。
     - `_` を K*（定数射）と読んでも、f ; K* は定数射で、向きは同じ。
   - 恒等射：U 10-14 00:36「f _ = f」は、`_` を合成の単位として読む読み。上の吸収と両立しない。だから `h _` の節（適用か合成か）は決まらない（Q18）。
   - 恒等射の役は `!_`：U〔答え〕10-15 23:16 と U 10-17 00:24 に合う。U〔答え〕10-16 22:09 の K とは食い違う（Q15）。
   - 穴は法則ではなく記法で、引数の位置での λ 抽象。
8. **分からないこと**：U 09-23 22:46「評価射は和の方になるから優先順位が積より下がる」の、数学としての正確な中身。

  - アリティ n は仮引数の数で、括りは1つで1と数える。実引数の並びの項の数 k が n のときは、前から順に仮引数へ当てて実体を作る。最後の仮引数が括りの関数は、k > n なら前の仮引数に1つずつ当てて、残りの並び全体を最後の括りが1つの List として受ける（`f 1 2 3` は `f [1 2 3]`、`map $[* 2] 1 2 3 4 5` は `map $[* 2] [1 2 3 4 5]` と同じ。`excess` は付けない）。前の仮引数には左から1つずつ当てる（`p3 : [a] [b ~bs] [c ~cs]` に `p3 1 [2 3] 4 5` を渡すと、`[a]` に 1、`[b ~bs]` に `[2 3]`、`[c ~cs]` に `4 5` が当たり、`p3 1 [2 3] [4 5]` と同じ実体になる）。k < n は、素の関数と同じく部分適用（L、残り n − k、足りない適用の印つき）。当てた物を覚えておき、残りが来た所で合わせて実体を作る（`(pair [1]) [2]` は `pair [1] [2]` と同じ実体。残りが多ければ、最後の括りが残りの並びを受ける）。最後の仮引数が裸の k > n は、素の関数と同じく前から n 個を当てて余り（`excess`。本体の根が A でなければ G12(b)、対に入れば G12(a)。余りの扱いは値の段、Q11）。撒く項があれば k は数えない（未知）。
  - 裸の仮引数は、今までどおり A。
  - 括りの中の名前は、渡された物の形で決まる。
    - **構造体**（全部の行が `名前 : 値` の括りか字下げのブロック）：裸の名前は、同じ名前の欄の生まれ（欄の右辺の種類）。欄が関数なら L で、名前で呼べる。同じ名前の欄が無ければ未知。`~rest` は、受けなかった欄の構造体（A）。
    - **List**（構築の並び・`,` の並び・2行以上の値の括りか字下げのブロック（1行が1要素）・文字列の字面）：裸の名前は要素の生まれ、`~rest` は同じ要素の List（A）。要素に L が見えたら、名前は未知。
    - **数**（数・文字の字面（`0u`・`0r`・`0b` を含む）と、それに値の印（`-`・`!!`・後置 `!`）や値の演算子（段13〜16・19〜22）を当てた物。それだけを括った `[3]` も同じ）：長さ1の List として受ける（`[x]≅x`）。裸の名前はその数、`~rest` は同じ要素の List。
    - **中身の見えない A**（裸の仮引数・`$` の番地・番地の字面・範囲・前置 `!` を当てた物・適用の結果（`[' k]` で引いた物を除く。引いた物は引かれた物の生まれを持つ、R26。合成の適用の結果は最後の適用の結果と同じ、§3.4）など）：裸の名前は未知、`~rest` は A。数と決まっていないので持ち上げない（器かもしれず、器なら要素に関数が見えるかもしれない）。
      - 番地の字面（`0x…`・`NxHHHH`）：§2 の字面の行は番地を数と別に挙げ、型でも `$` が返す値と同じ Address（D type_system.md §2）。指す先が器かもしれない。
      - 前置 `!`：`!_` は恒等射（R18）で、`_` でない物に当てると `_` になる（D operator_table.md）。だから `!x` は数にならず、x が `_` になる物（`1 < 0`・`/ 0`）なら関数になる。数と読むと、`f !(1 < 0)` の実体で `h 5` を黙って構築と読む。
    - **L か未知**：どの名前も未知。
  - 実体の本体の根が A なら、適用の節は A。そうでなければ未知（§3.4 の素の関数の k = n と同じ）。
  - 再帰は、実体ごとに A と仮置きして一巡する（§3.4）。同じ形で自分を呼べば、同じ実体の仮置きを引く。
  - 合成の中の括りの関数も実体を作る（Q24 の案1）。合成は適用の繰り返し（§3.4、R11）なので、最初の関数は並びを受け（上の当て方のどれか）、後ろの関数は前の結果を1つ受ける。
    - 前の結果が A なら、その desc を受ける。素の関数と括りの関数の実体の結果は中身の見えない A なので、括りの名前は未知。`[' k]` で引いた物なら、その形を受ける（R26）。
    - 前の結果が L か未知なら、未知を受けて実体を作る（Q27。最初の関数が足りたか決まらなくても作る）。
    - 最初の関数そのものが撒く項を受ける括りの関数なら、k が数えられないので作らない（Q29）。

- **断る側に倒した所**（どれも門で名指しする。黙ってどれかの読みにしない）
  - List の要素に L が見えるとき：生まれでは L だが、U [2026-10-14 11:01]（リストの関数は番地、`@(procs ' 0) 5`）とは食い違う。だから未知にする。`$inc` で入れた要素は A なので、ここに当たらない。
  - 構造体に同じ名前の欄が無いとき：名前で当たらなかった名前を前から当てるかは、どの言葉にも無い。
  - 空の括り `[]` は、List に数えず中身の見えない A にした。長さ1の括りと1行の字下げのブロックは、中の物の形（`[3]` は数、`[m]` は m の形）。
  - 数の List と数は、形としては同型（形は長さに依らず、数は長さ1の List）だが、鍵は分けたまま（`f 3` と `f [1 2 3]` は読みの同じ2つの実体になる）。だから要素に数と数の List が混ざった `[[1 2] 3]` は形の違う要素の List で、要素は中身の見えない A（断る側）。
  - 括りの中の括り（入れ子の分解）・2行以上の括りの仮引数・末尾でない `~rest` の名前は未知。
  - 要素に L が見えるかは、要素の中の器の中まで見る（§2「中身が見える器」と同じ見方）。L か未知が見えたら名前は未知。
  - 構造体とも List とも読めないが中身の見える器（行の混ざった括りか字下げのブロック・同じ名前の欄が2つある構造体・欄の右辺が撒く項・撒く項を含む並び）は、名前は未知、`~rest` は中身を持ち越す（撒けば §3.3 の手順1 の G7）。
  - 書いた形が届くより深い形を渡す実体（`f : [x ~xs] ? f [xs xs]` は形が1段ずつ深くなり、実体が有限に収まらない）と、同じ関数の確定した実体が多すぎる形は G7（実装の守り。数え方と値は下の「実装で決めた所」、Q25）。書いた形は、どれだけ深くても断らない。
- **実装で決めた所**
  - 裸の仮引数の位置は、形に数えない（いつも A）。
  - 実体の鍵には、欄の関数の出どころ（書いた本体と、定義した所の範囲）まで入れる。本体の根の違う関数を同じ実体にしない。
  - 括りの関数の部分適用の鍵は、元の関数の出どころと当てた物の形（裸の仮引数の位置は A）。当てた物の違う部分適用は別の関数で、欄に入れて渡せば別の実体になる。鍵は形の鍵と同じく番号に寄せて綴る（入れ子の部分適用で長さが倍々にならないように）。合成の鍵も同じ（同じ部分適用を2つ並べた合成を当てた部分適用の鎖で、倍々にならないように）。
  - 合成の後ろの関数の本体の根は、前の結果が A のときだけ引く。L か未知の後ろでは、括りの関数の実体だけを作る。
  - A の間に引いた根が後ろで使われなくなる形と、未知の後ろの実体の本体が引く根も、外れた仮置きに頼った答えを解き直すので、定義の順で割れない（Q28 で閉じた）。
  - 仮置きの上で決まった根は、名前の無い関数が値として渡った物も、仮置きが外れたら、確定した値で解き直す（名前の無い関数は記録の地図に載らないので、閉包が本体を同じ範囲で解き直す）。
  - 根が未知の答えは解き直さない（いちばん下なので変わらない）。だから外れは記録ごとに一度だけで、同じ記録の解き直しは外れと例外の数を超えない。それが枠を積んだ記録の数を超えたら、読みを決めずに resolve-again-limit で名指しして断る（実装の守り。試験と確かめでは届かない）。
  - 実体の守り（2026-10-20 にまとめ直した。主の Claude の提案「守りを、枠の積み方ではなく形そのものの性質で決まる形にまとめ直す」）。値は言語の規則ではなく実装の守りで、決めていない。守りは4つある。深さと総数は、作る実体の鍵（渡された形）と確定した答えだけで決め、枠の積み方や作った実体の履歴では決めない。だから当たるかは、ほかの門と同じく本体と前提の値だけで決まり、§3.4 の不動点の理屈の中にある（どの定義・行から先に解いても同じ）。作った実体の数と入れ子の数は、止まるための資源の守りで、計算の道で決まる（理屈の外。G7 ではなく別の reason で断る）。
    - **深さ**：作る実体の鍵の入れ子が上限を超えたら、その実体を作らずに G7。上限は（32 × 書いた括りの関数の数 + 1）× 書いたいちばん深い形で、解く前にソースだけから決める。普通の門なので、根の種類を解く所では未知になり、木を残す段で同じ鍵にまた当たって、呼んだ行で、通った実体を呼んだ順に名指しする（R25）。
      - 数え方：中身の見えない A・未知・数は 1 段。構造体と List は、中身のいちばん深い物の 1 段上。関数は、書いた所の範囲の深さ（実体の中で書いた閉包の鍵は、書いた所の範囲の鍵＝実体の鍵を持つので、その実体と同じ段）。ファイルの範囲で書いた関数と、範囲を鍵に持たない関数（点なし・頭の前置 `@`・既定値のある関数）は 1 段。括りの関数の部分適用と合成は、元の関数・当てた物（裸の仮引数の位置は A）・中の関数のいちばん深い物の 1 段上。素の関数の部分適用と穴は、元の関数と同じ（鍵に当てた物が入らない。裸の仮引数は A）。
      - 門で見る実体の深さは、括りの仮引数に当てた物のいちばん深い物。関数を書いた所の深さは入れない（書いた所の実体は、その実体の門で見てある）。だから深い実体の中で書いた括りの関数に数を渡す（`p : [a] ? [[b] ? b] [1]` に 31 段の字面）のは通る。実体の範囲の深さ（中で書く閉包の段）は、当てた物の深さと、書いた所の範囲の深さの大きい方。
      - 書いたいちばん深い形は、ファイルに書いたどの形（括り・字下げのブロック・並び・`,` の並び、関数の本体の中も）の深さも下回らない数で、鍵の深さと同じく数える。名前は、ファイルの値の定義なら右辺の書いた深さを通す。定義が前の定義を指して深くなる鎖（`q1 : pp [f : q0] [f : q0]`…）も書いた分に数える。値の定義の深さには、関数の本体（`?` の右）と `:` の左を入れず、印の付いた名前（`$w`・`@w`・前置 `~`・後置 `@` は種類を引かず、値の印・後置 `~` を付けた物は鍵では形の無い値か撒く項）は辿らないので、辿る名前の輪は値を含む種類の輪（どの並べ方でも name-cycle、Q30）だけで、そこは 0 で切る（前は `$` か後置 `@` で互いを指す値の定義でも切ったので、上限が行の順で変わった。確かめ 2026-10-20 の4回目・5回目）。`x ' k` の右が裸の名前か字面の整数なら鍵（欄の名前か位置、R26）なので、名前として辿らない（前は値の定義の名前と同じ綴りの鍵を辿り、上限が並べ方で割れた）。ほかの右（`x @ k` の右も）は解くので、そこに書いた形と `?` も数える（その次の版は右を丸ごと数えず、`1 @ [f …70 段…]` を G7 で断った。確かめ 2026-10-20 の6回目）。文字列の字面は文字の List なので 2 段に数える。関数の本体の枝の条件（`:` の左）に書いた形も数える（2項以上の条件は解くので。前は数えず、条件に書いた深い字面を断った。確かめ 2026-10-20 の5回目）。数え方は鍵の深さより浅くならない側に倒す。入れ子の道（実体の本体が実体を作る道）で括りの関数を1つ通るたびに、呼んだ所に書いた形の分までしか深くならない（受けた物を書いた形の中に入れて渡すだけ）。呼んだ行に書いた形が書いたいちばん深い形までなので、どの括りの関数も 32 回までしか通り直さない道（括りの関数を 32 × 書いた括りの関数の数 回まで通る道）は、上限までしか届かない。前の版の深さの守り（同じ `?` の実体の入れ子 32）を通った形は、どれも上限を越えない。越えるのは、同じ `?` を何十回も通り直して形が深くなり続ける再帰だけである（前は「(括りの関数の数 + 1) × 書いたいちばん深い形 + 32」で、輪の中で深くなってから戻る有限の再帰を断った。確かめ 2026-10-20 の4回目。その次の「32 ×（括りの関数の数 + 1）× 書いたいちばん深い形」は、この道の届く深さより 31 × 書いたいちばん深い形だけ大きく、形が深くなり続ける再帰をその分遅く断った）。
      - 断る形：形が1段ずつ深くなる `f : [x ~xs] ? f [xs xs]`。閉包が前の実体の中で書かれ、鍵が1段ずつ深くなる `f : [s] ? f [s : [y ? s y]]`（形の綴りはどれも `{s:L}`）。上限に 32 × 書いた括りの関数の数を掛けたので、深さの門が入れ子の数の守り（再帰の入れ子 256）より先に当たるのは、1回に2段以上深くなる再帰か、書いた形が浅い小さなファイルだけで、1段ずつ深くなる再帰は、ほぼいつも入れ子の数の守りで断る（断るのは変わらない）。断らない形：書いた字面（何段でも）、書いた部分適用と合成の鎖、値や閉包を欄で渡す別々の関数の鎖、減っていく形の再帰（入れ子の字面を1段ずつ剥がす）、輪の中で深くなってから戻る有限の再帰、素の関数を挟む鎖（`f0 : x ? hb [s : f1]`…）、形の深くならない輪（欄の入れ替え）。前（同じ日のまとめ直しの後）は上限を固定の 32 にしていたので、32 段より深い字面や書いた鎖を、有限で値の決まる形でも断った（主の Claude の指摘に、利用者「対応お願いします！」。2026-10-20）。
      - 前は同じ `?` の実体の入れ子を数え、どの順に解いても同じ段になるよう数え直していた（枠の並び・記録の下の入れ子・輪の頭の段・当たった記録を resolve の最後に断る作り）。それでも輪の中は近似で、上限のちょうど上では入口で割れえたうえ、当たるかが枠の積み方で決まるので、§3.4 の理屈の外に置いていた。
    - **総数**：深さが上限の内でも、形が枝ごとに増えると実体は 2^深さ になる（Q25）。同じ `?`（書いた所。どの範囲で書いた物も1つ）を通って呼んだ、確定した実体が 512 個を超えたら G7。同じ綴りの関数は実体を分け合うが、呼んだ `?` のそれぞれで数える（綴りで数えると、別々に書いた2つの関数が上限を分け合う）。確定した実体は、最後の木の道にあると言える呼び出しの実体である。呼んだときに解いている途中のどの関数も仮置きに頼っておらず、門に当たる実体を呼んだ後でもない物、頼っていた仮置きが全部当たった物、木を残す段で呼んだ物。確定した値だけを読んで辿った道は木を残す段がもう一度辿るので、どれも最後の木の実体である。数えない物は2つ。外れた仮置きの上でだけ作った実体は、確定した値の上では作られない。門に当たる実体を呼んだ後ろの実体は、木を残す段がそこで呼んだ行ごと断るので、最後の木に無い（根の種類を解く所は、門を未知にして先へ進む）。だから断るのは、最後の木の実体が 512 個を超えるときで、どの順でも同じ。当たった実体と行は解く順に依るので、行と形では名指しせず、`?` の名前（名前の定義なら名前、括りなら綴り）だけを言う。
      - 枝ごとに形が増える再帰（`g : [x ~xs] ? (g [[a : xs] [a : xs]]) , (g [[b : xs] [b : xs]])`）は、最初の枝を深さ優先で降りて深さの門に当たる。だから最後の木はそこで断る形で、残りの枝は最後の木に無い。根の種類を解く所の増え方は作った実体の数の守りで止まる。最後の木の深さの門は、守りに当たった答えを読んだ所（下の汚れ）で出るので作り物と見分けられず、作った実体の数の守り（`instance-work-limit`）を言う。
    - **作った実体の数**：総数に数えない実体（仮置きに頼った物と、門に当たる実体の後ろの物）は、増え続けても総数では止まらない（同じ形で自分を引いてから枝ごとに増える `g : [x ~xs] ? (g xs) , (g [[a : xs] [a : xs]]) , (g [[b : xs] [b : xs]])` の後ろの実体は、どれも g の仮置きに頼る）。だから同じ `?` で作って外れていない実体（確定した物、まだ仮置きに頼っている物、門の後ろの物）にも 1024 個の上限を置き、超えたら `instance-work-limit` で断る。頼っていた仮置きが外れたら、その実体は数から外す。外さないと、外れた仮置きの世界ごとに実体が積み増し、上限の前後で定義の順で割れた（f が g の仮置き・h の仮置き・確定した値の3つの世界で同じ p の実体を 342 個ずつ作る形は、g → h → f の順に解く並べ方だけ 1026 個で断った。確かめ 2026-10-20）。
    - **入れ子の数**：形が深くならないまま、解いている途中の実体が長く入れ子になる再帰（欄 7 つの並べ替え。形は 5040 通り）や、それを関数を跨いで呼び合う再帰は、JS のスタックを溢れさせ、解き直しと輪の記録の手間も入れ子の長さの2乗ほどで増えた（前の深さの守りを外した後。確かめ 2026-10-20）。だから、再帰の入れ子（根の種類を解いている実体と木を解いている実体のうち、同じ `?` の2つ目から先の数の和）が 256 を超えたら、`instance-nest-limit` で断る。値だけを渡す別々の関数の鎖は、それぞれの `?` が1つずつなので数えず、前の版と同じく何段でも通す。数えるのは素の名前つき関数の本体と値の定義を解く枠の間だけで、その枠に入ると数え直す（前の版の深さの守りは、括りの関数の実体でない枠（名前の無い関数の解き直しの枠も）で数えるのを止めていた。ここで数え直すのは、1つずつしか積まれない枠だけ）。どちらの枠も1つずつしか積まれないので、再帰の入れ子の和は（その数 + 1）× 256 までに収まる（前は枠を跨いで数え、素の関数を挟む hb の鎖 `fi : x ? hb [s : f(i+1)]` を 257 個で断った。前の版は通す。確かめ 2026-10-20 の6回目）。スタックが溢れたら（鎖が長いか、実体1段の本体が重い。書いた深さを数える所で、値の定義の長い鎖を辿って溢れても）、内部の例外にせず、`resolve-stack-limit` で断る。
    - 守りに当たったら、当たった所は門と同じく未知になり、当たった `?` では、それから新しい実体を作らない（ほかの `?` は解き続ける）。前段（名前の種類と素の関数の本体の根）でも行でも、断ってもその先を解き続ける（総数はファイル全体の最後の木の性質なので。解き直しの守りと値を含む輪だけは、そこで止める）。守りの断りを捕まえた枠の答えと、それを読んだ計算には「汚れ」の印を付ける（守りが無いときと答えが違いうる）。汚れた計算の呼び出しは総数に数えず、汚れた所で出た門と値を含む輪は作り物かもしれないので後に回す。言うのは、解き直しの守り → 値を含む輪 → 総数 → 最初に断った行の門 → 資源の守り（作った実体の数・入れ子の数・スタック）→ 汚れた所の輪と門の順。同じ守りが2つの `?` で当たったら、名前の小さい方を言う。名指しは `?` の名前だけ。資源の守りを汚れていない行の門の後に置くのは、それが最後の木の門だから。輪を守りの前に置き、止めるのを当たった `?` だけにするのは、どの順でも見つかる輪と、ほかの `?` の守りを、先に当たった守りで覆わないため（前は総数の断りが先に投げ上がるか、全部の新しい実体を止めたか、最初に断る行や前段の断りで止めたので、輪・2つ目の守り・総数を見る前に止まる並べ方があった。資源の守りで未知になった根から出た門を、資源の守りより先に言う形もあった。確かめ 2026-10-20）。
- **例**
  - `m :` ⏎ `⇥say : x ? x * 2` ⏎ `⇥other : 1` と `a : [say] ? say 21` で、`a m` の実体の本体は `(apply say 21)`、`a m` は A。
  - `f : [x ~xs] ? [f xs] x` と `f [1 2 3]`：x は数、xs は数の List、本体は `(construct [f xs] x)`。`f 3`（数）も同じ読みで、実体は数と数の List の2つ。
  - `pair : [a ~as] [b ~bs] ? a + b` と `pair [1 2 3] [10 20]`：A。
  - `fs : inc , double` と `g : [h ~hs] ? h 5` で `g fs`：h は未知なので、呼んだ行で G7。
  - `w :` ⏎ `⇥1 2` ⏎ `⇥3 4` と `f : [x ~xs] ? (x ' 0) 1` で、`f w` の実体は `w : [1 2 ⏎ 3 4]` と同じ `[[N…]…]`（1行が1要素で、平らにしない）。

### R25 実体の無い本体は読まない — 92%
- **文面**
  - 括りの関数の本体は、実体を作るとき（呼ばれたとき）にだけ解く。
  - ファイルの中で一度も呼ばれない括りの関数は、本体を書いたまま残し、断らない。公開（`#`）した関数の実体は、取り込んだ側の呼び出しが作る。
  - 実体を作って門に当たったら、呼んだ行で断る。どの関数をどの形で呼んだかを名指しする。
    - 呼んだ所が素の関数の本体なら、その定義の行で断る。
    - 実体の中から別の実体を呼んで門に当たったら、いちばん外の呼んだ行で、通った実体を呼んだ順に名指しする。名指しには、呼んだ行で使った名前を使う。
  - 定義の行に描く `inst` は、その `?` を通って呼ばれた形だけ。同じ綴りの別の関数は答えを共有するが、呼ばれていない方は `defer` のまま。
    - どの `?` を通って呼ばれたかは、実体を作った側の物ではなく、その呼び出しで渡した物で決まる。分け合った実体の本体の中で、欄に入れて渡した関数を呼ぶとき（`h : [f] ? f [1] [2]` に `h [f : pair]` と `h [f : pair2]`）は、`pair` と `pair2` の両方の行に描く。行の順を入れ替えても、全部の木・種類・診断・門は変わらない。門の名指しも、その行で渡した物の名前で言う。
  - 1項の `:` の左と既定値は解かない（P3）。そこで括りの関数を2項以上の並びの項として呼ぶ形は、実体が作れないので G7。1項だけ書いた物は値なので断らない。G7 を探して覗く所の輪の扱いは Q30。
  - 読まない本体の中の未定義の名前は information を出さない（読まないので）。P2 の隠し・同名は、読まない本体でも見る（名前の表の話で、本体を読むことではない）。
- **理由**
  - 本体の読み（適用か構築か）は、渡された物の生まれの関数である。呼ばれる前に読みを1つに決めると、関係より先に対象を定めることになる。これは `__` の短絡（適用する前に関数の値を決めた）と同じ誤りである。
  - 未実行の関数は `_` と同型である（pattern_guide.md「Sign上では **未実行関数 ＝ Unitと同型**」）。矛盾（始対象）ではない。門で断るのは、実体を作って読みが決まらなかったときだけにする。
  - 素の関数は、仮引数が全部 A なので形が1つしかなく、実体は定義の所で1つに決まる。だから今までどおり定義の行で解く。
- **出どころ**
  - U 2026-10-19：「一度も呼ばれていない関数の本体は、分からないまま断る。」への「ここがどうしてexport出来ないのかは根深い。」
  - U 2026-10-17「やはり写像という言葉が良くないんだな… 対象を定めたら、正しさは失われるんだ。」
- **木**：§1.3 に足す。呼ばれない括りの関数は、本体を書いたまま `(defer …)` で包む。呼ばれた形があれば、形ごとに `(inst 形 本体)` を並べる。

### R26 `'` で引いた物の種類は、引かれた物の生まれで決まる — 91%
- **文面**
  - `x ' k` で x の形が見え（R24 の構造体か List）、k が字面の整数か裸の名前のとき、引いた物の種類は、その要素か欄の生まれ（R24 と同じ決め方）。

### 6.4 実装で気を付けること

1. **種類を計算する順**
   1. ファイルの定義を集める（P2）。
   2. 名前の種類を決める（`?` なら L、それ以外は右辺の根）。
   3. 各**素の**関数の本体の根の種類を決める。再帰は A と仮置きして一巡し、食い違えばその関数を未知にし、外れた仮置きに頼った答えは解き直す（§3.4）。括りの関数の本体は、実体を作るときにだけ解く（R25）。
   4. 各並びを解く。
2. **節の印**：`excess` と `partial` は節が作られた時に付け、対に入る時に G12(a) と G2(b) で見る。印のある節でも、根になるのはよい。
3. **門の時機**
   - 前検査で見る：G4・G6・G7・`!_`・`fs~`。
   - `_` の段で見る：G5。
   - 縮める時に見る：G1・G2・G8・G9・G10・G12。
   - 最後に見る：G11。
4. **穴**：並び全体の前処理で見つける。括りの中の行も、その行全体で見る。穴の節は対に入らない（括りに入れば L の葉になる）。
5. **「未知」**：隣と結ぶ時だけ断り、根なら通す。だから `@a b c` が書ける。
6. **後置 `~` の中身**：名前の定義の右辺が字面の器なら、名前を通して見る。
7. **試験の層**：木の試験（6.3）と値の試験（「値」の列）を分ける。値の試験は、§3.7 の値の段が決まってから入れる。
8. **断られる見本**：「今は断る」試験として置く。§5 の問いの答えが出たら、その行を通る側へ移す（U〔答え〕09-27 22:10「あとでいかようにでも直しやすい」）。
