# 関数定義とその型について

Signでは、関数定義の方法が多岐にわたって存在する。  
よって、これら関数定義の方法について、具体例を交えたドキュメントをここに記す。

## ポイントフリー記述

全ての演算子を関数として扱う場合、任意のカッコで演算子を囲むことで関数として扱う。  
この時、前置演算子は、`[<op>_]` 後置演算子は `[_<op>]`と記述する。  
ポイントフリー記述の二項演算子は、複数の引数を貪欲に演算する。  
単項式の後ろに`,`を付けたポイントフリー記述は、そのすべてに適用される。

```Sign

` Sumと同等
[+] 1 2 3 4 5

` mapと同等
[* 2,] 1 2 3 4 5

` 否定する関数
[!_] 2 < 3

` 階乗する関数
[_!] 5

` ポイントフリーの合成はストリームで繋がる（list_model.md §2.4③）
` 「2倍の写像」と「合計の畳み込み」が1回のパイプラインになる
[* 2,] [+] 1 2 3 4 5

` 括弧で括ると値（List）に固まる。畳み込むには後置~で再展開する
[+] ([* 2,] 1 2 3 4 5)~
```

## ? 演算子を用いた定義方法

`?`演算子は、左辺に引数リスト、右辺に本体を有する演算子と解釈できる。

```Sign

f : x y ? x + y
```

### match_caseの記述

`?` の右辺を改行・インデントブロックを挟むことで、本体内の : 演算子はmatch_caseとなる。

```Sign

f : x y ?
	x > 3 : x - y
	y < 3 : x + y
	x y
```

### デフォルト引数の記述（ローカル変数代わりにも使える）

`?` の左辺インデントブロックは : 演算子がデフォルト引数の記述となる。

```Sign

f :
		x
		y : x + 1
		z : y + 1
		~rest
	? x y z rest~
```

> [!IMPORTANT]
> **デフォルト引数には純粋な値式 + Input までが使用可能。Output 演算子（`#`）は禁止。**
>
> 理由は**評価が条件付きだから**である。デフォルト式は、その引数が省略された（Unit が渡された）ときにだけ評価され、呼び出し側が値を渡せば**評価ごと飛ぶ**。
>
> ここに `#`（ストア）を書くと、書き込みが起きるか起きないかが**呼び出し側の引数の数で決まる**ことになる。呼び出し側からは見えない制御フローであり、原理3（危険は明示的なオプトインでのみ）に反する。Output が必要な処理は関数本体（`?` の右辺）に書くこと。本体は無条件に評価されるため、この問題が起きない。
>
> Input（前置 `@`）が許されるのは、そこが**状態の初期化を書く場所**だからである（下記「仮引数リストは関数の状態ベクタである」）。「渡されなければ環境から読む」はこの機構の本来の仕事にあたる。加えて、MMIO のレジスタは読むたびに値が変わりうる（clear-on-read もある）ため、読み出した値を名前に束縛できないと、使用箇所ごとに再読み出しすることになり**正しさ**を損なう。
>
> ```sign
> ` ❌ 禁止：デフォルト引数内での Output
> f :
>     x : some_ptr # 42   ` ← コンパイルエラー（原理4）
>   ? x
>
> ` ✅ 許可：Input はデフォルト引数に書ける
> f :
>     x : @some_ptr
>   ? x
>
> ` ✅ 正しい：Output は本体に書く
> f :
>     x
>   ? some_ptr # x
> ```

### 仮引数リストは関数の状態ベクタである

Sign にはローカル変数を定義する専用の構文が**無い**。仮引数リストのデフォルト引数がその役割を兼ねる。これは機能の不足ではなく、原理1（RISC as-is）の帰結である。

レジスタマシンには「ローカル変数」と「引数」の区別が存在しない。どちらもレジスタであり、引数が届く場所がそのままローカルの住処になる。専用構文を設けることは、ハードウェアに無い区別を言語が発明することにあたる。さらに、ローカルを呼び出し側から**隠す**には退避や遮蔽の命令が要る——外から触れるままにしておく方が as-is であり、かつ無料である。

したがって、デフォルト引数として書いたローカル変数は**呼び出し側から上書きできる**。これは穴ではなく機能である。

```sign
f :
	x
	y : x + 1
	z : y + 1
 ? z

f 3          ` → 5     すべて計算する
f 3 10       ` → 11    y を渡すと y の計算を飛ばす
f 3 10 99    ` → 99    z を渡すと z の計算も飛ばす
```

ここから3つの性質が導かれる。

- **再開可能性**：途中の値がすべて名前を持ち、その名前がそのまま入口になる。関数はブラックボックスではなく、任意の中間状態から再開できる計算になる
- **メモ化・部分評価**：デフォルト式は「渡されなかったら計算する」節である。既に値を知っている呼び出し側が渡せば、その計算は実行されない。専用の機構をひとつも足さずにキャッシュが手に入る
- **蓄積再帰の素直な表現**：`go acc rest` のような再帰は「状態を渡して自分を再開する」ことに他ならない。初回の呼び出しだけが `acc` を省略してデフォルトを取り、以降の呼び出しは状態を渡す

```sign
go :
	acc : 0
	rest : __
 ?
	(rest) : go (acc + (rest ' 0)) (rest ' 1~)
	acc

go __ [1 , 2 , 3 , 4]   ` → 10    最初から
go 6 [4]                ` → 10    途中の状態を渡して再開
```

> [!CAUTION]
> 状態ベクタには、**失敗と区別が付かない値**を初期値として置かないこと。
>
> デフォルト値に `__` を置くと、その引数の定義域は `__` まで持ち上げられる。以降その関数は、正当な「空」と、失敗して `__` に落ちた値とを区別できない。実例は [`examples/n-queen/n_queens.sn`](examples/n-queen/n_queens.sn) を参照。
>
> リストを受ける引数であれば、`[~xs]` や `[x ~xs]` のように**分解の形で宣言する**方がよい。Unit は分解すべき構造を持たないため、失敗値がそこを通れなくなる。

### デフォルト引数と、match_caseの記述は共存可能。

```Sign

f :
		x
		y : x + 1
		z : y + 1
		~rest
	? 	x > 3 : x - y rest~
		y < 3 : x + y rest~
		z rest~
```

これらの関数にそれぞれ型を与えた方がよい。

## 関数適用時

デフォルト引数を持つ関数の適用だけが異なる挙動となる。

```Sign

` 通常は部分適用となる動作（静的脱糖によりラムダに変換される）
f : [+] _ _ 3 4 5  ` $p0 $p1 ? [+] $p0 $p1 3 4 5 と同等
f 1 2              ` 評価結果: 15

g :
		x
		y : x + 1
		z : y + 1
	? x y z

` g はデフォルト引数を持つため、これらはアリティ計算から除外される。
` よって、デフォルト引数以外の実引数を渡すだけで自動的に評価が実行される。
g 3   ` 評価結果: 3 4 5

` 例えば、予期せぬ演算で __（Unit値）が算出された場合、デフォルト引数を持たない関数は __ に短絡評価される。
` （Unit伝播・即時崩壊）
f 3 < 2 1   ` 3 < 2 が __ になるため、f __ 1 となり、評価結果は __ に崩壊する

` デフォルト引数を持つ関数の引数に __ が渡された場合、暗黙でデフォルト引数の定義値による評価が行われる（フォールバック）。
g 1 3 < 2   ` 3 < 2 が __ になるため、g 1 __ となり、y にはデフォルト値 x + 1 (2) が適用される。
            ` 評価結果: 1 2 3

` 可変引数（~rest）に __ が渡された場合の挙動：
` 可変引数はデフォルト引数と「同じ」ように振る舞います。
` つまり、__ が渡された場合は完全性公理による崩壊は起きず、暗黙のデフォルト値である __（空リスト）へフォールバックし、
` 関数は通常通り実行されます。
h : x ~rest ? x rest~
h 1 __      ` 評価結果: 1 （__ は空リストとして扱われ、rest~ で展開されると消去されるため）
```

## カッコ囲みの仮引数リストによるチルダ省略

仮引数リスト全体をカッコで囲んで定義した関数は、実引数として渡されたリストや構造体を、呼び出し側で後置チルダ `~`（展開）を付与することなく、そのまま直接受け取ることができます。
この構文の場合、参照が2つ以上あっても参照の数だけカッコで囲むことで、参照の展開による境界を明示することが出来ます。
もちろん、デフォルト引数やmatch_caseとの共存も可能です。
```Sign
` 仮引数リストをカッコで囲む
sum_list : [x ~xs] ? xs & x + sum_list xs | x

` 呼び出し側はチルダなしでリストを渡せる
sum_list [1 2 3 4 5]  ` 評価結果: 15

` デフォルト引数・match_caseとの共存例
func_mixed :
		[
			x
			y : x + 1
			~z
		]
	?
		x > 3 : x - y
		y

func_mixed [5]      ` 評価結果: -1 (x=5, y=6. x > 3 なので 5 - 6 = -1)
func_mixed [2]      ` 評価結果: 3  (x=2, y=3. x > 3 は偽(__)のため、y が評価される)
func_mixed [2 10]   ` 評価結果: 10 (x=2, y=10. x > 3 は偽(__)のため、y が評価される)
```

## 構造体メンバーの一致による自動バインディング

仮引数リスト全体が `[ ]` で囲まれている関数に構造体を実引数として渡す際、構造体のメンバー名（キー）と関数の仮引数名が一致している場合、順番に関わらず自動的に名前ベースで分割代入（バインド）が行われます。
この構文の場合、参照が2つ以上あっても参照の数だけカッコで囲むことで、参照の展開による境界を明示することが出来ます。
もちろん、デフォルト引数やmatch_caseとの共存も可能で、Listの時の仮引数リストでの展開と同様の構文で定義できます。

```Sign
` 構造体を受け取る関数、~obj は必須ではないが、定義時に渡した構造体以下の構造体を保持したい場合に使う。
calc_diff : [foo bar ~obj] ? foo - bar

` メンバー名を一致させた構造体をそのまま（チルダなしで）渡す
calc_diff [
	bar : 20
	foo : 100
]
` 評価結果: 80 (foo = 100, bar = 20 が自動で紐づく)

func_mixed :
		[
			foo
			bar : foo * 2
			~obj
		]
	?
		foo > 3 : foo - bar
		bar

func_mixed [
	foo : 4
]
` 評価結果: 8 (foo = 4, bar = 8. foo > 3 は真のため、foo - bar が評価される)

```
